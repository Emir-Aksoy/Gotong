# Atong 时间证据链设计

方向：M。状态：用户已确认总体设计，并明确采用服务器时区；按独立里程碑实施。

## 用户约束

- 增强事件记忆与对话时间辨识，不以扩大上下文作为解决方案。
- 只改进今后的记录和使用方式。**不恢复、不推测、不回填已经丢失的历史记忆。**
- 旧数据保留原样；已有时间字段只按原有含义解释，缺失的事件时间保持未知。
- 只有用户原话或明确确认的内容可以作为长期事实来源。助手自己的回复不是用户事实依据。
- Gotong 仍是模型无关网络；时间解析、事件整理和上下文呈现在 Atong / personal-memory 层完成。
- 本阶段不修改生产凭据、不自动部署，不引入新的外部记忆服务。

## 已核验问题

核验基线：生产与本地均为 `0b92bce1`。

1. `session-window.ts` 保存 `at`，但 `render` 输出只包含角色与正文。
2. `frozen-block.ts` 的普通条目渲染不显示时间；相同正文、不同 `ts` 的单条记忆产生相同提示词。
3. `consolidate-tiered.ts` 与 `atomic-facts.ts` 向整理模型提供正文但不提供逐条原始时间及可验证来源。
4. `novelty.ts` 只比较文字相似度；不同日期的“今天吃了烤肉”会被判为重复。
5. `recall` 会显示存储时间，但不区分事件发生时间、消息时间、摘要写入时间。
6. 已存在会话窗、双时态有效区间、联想网和记忆单，不另建平行架构。

上述是代码和合成样例证据，不是对用户两次实际误答的逐条归因。未检索私人历史对话。

## 第一阶段目标

把“何时发生”“何时说过”“何时写入”分开，在采集、整理、折叠和渲染中不混淆、不伪造。下一阶段再增加时间范围检索和统一 token 预算。

### 1. 数据契约

复用 `MemoryEntry.meta`，新增版本化 `temporal` / `evidence` 元信息，由一个小型纯函数模块负责校验、读取与格式化。

| 信息 | 定义 | 缺失策略 |
|---|---|---|
| 原消息时间 | 可信本地接收入口保存的时间，并标明是接收时间还是渠道提供的发送时间 | 未提供可信值就未知，不能用回复完成时间冒充 |
| 记录时间 | 现有 `MemoryEntry.ts`，表示这条记录写入时间 | 保持现有含义 |
| 事件时间 | 用户陈述明确支持的日期、日期区间或未知 | 不从记录时间自动推导 |
| 相对时间原词 | 例如“上上周”“昨天” | 保留原词，不在每次回答时重新锚定 |
| 时区与依据 | 采用服务器解析出的 IANA 时区，并随新记录固定保存 | 无法解析时明确采用 UTC，不猜用户所在地 |
| 精度 | 日、周/区间、具体时刻、未知 | 不将周范围压成某一天 |
| 来源 | 所属成员作用域内的来源 ID、说话者、有限长度原文证据 | 来源不可读时不得声称已核验原文 |
| 状态 | 原陈述、后续明确纠正、发生过但时间未知 | 不用最近写入覆盖所有历史事件 |

事件时间与现有 `validFrom` / `validTo` 不混用：后者描述事实何时有效或被替代，前者描述事件何时发生。正文仍留在原存储中，引用不变成跨用户读权限。

### 2. 时间解析与服务器时区

- 明确绝对日期可记录为本地日历日期，不强行编造时刻；带偏移的具体时间可转换为 UTC。
- “今天/昨天/上周/上上周”必须绑定原消息时间和当时服务器时区；“上周”采用周一至下周一的半开区间，并保留原词与解析规则。
- 用户于 2026-09-11 明确选择服务器时区，不新增成员时区设置。新记录固定当时的服务器时区；以后修改服务器时区，不重新解释旧记录。
- 没有可信原消息锚点时，保留相对表达且事件时间未知。记录完成时间和恢复执行时间不能冒充用户原消息时间。
- 模型只可从用户证据提出候选事件；确定性校验器确认来源 ID、证据片段与日期约束。没有足够证据时不晋升为已确认事件。
- 热路径不增加 LLM 调用。复杂自然语言事件提取复用现有维护调用；不手写无界自然语言日期解析器。

### 3. 采集与去重

- 新会话消息保留可信时间，在模型可见历史中加简短时间标签；不改变用户正文所表达的内容。
- 同一来源消息的重试可以幂等处理；不能仅凭文字相似就断言两条消息是同一事件。
- 同正文、不同发生时间必须保留为不同事件；有相对时间、时间未知或事件身份不明时，禁止跨消息的有损折叠。
- “再次说起同一件事”的合并，必须有明确来源关联或同一事件标识，不能只看最近出现的关键词。
- 新旧条目之间不能借折叠给旧条目补出事件日期；旧数据不迁移、不批量改写。
- 事件不是偏好：用户说“吃了一次烤肉”不能直接成为“喜欢烤肉”。

### 4. 整理与来源保留

- 整理输入逐条提供来源、说话者、原消息时间及事件时间，时间未知明确标出。
- 整理输出必须关联输入中实际存在的来源，并保留有界的证据摘录；不能仅写 `atomicFact: true`。
- 助手消息可以作为对话背景，不能独立生成用户的长期 semantic fact。
- 多日期事件不揉成无日期画像。单次事件用事件型条目保存，稳定偏好用 semantic fact 保存，两者复用现有存储而不新建数据库。
- 删除被整理的原条目前，先检查新输出是否保留该条所需的事件与来源；失败则不执行这次有损整理。不为了通过验收而默默放宽现有存储预算。
- 摘录、来源列表和条目大小均设固定上限；无法在上限内保持证据时，分批整理或保留源条等待后续处理，而不是截断日期字段。
- 原始证据仍可能按用户既有删除/保留政策被清理。来源已失效时明确不可用，不再检索其它用户或备份来补足。

### 5. 呈现规则

统一时间格式器供 frozen block、recall、记忆单与整理提示词使用，避免每条路径对同一日期有不同解释。

例如只有周范围时：

> 事件：吃烤肉；发生：某周的日期范围；告知：原消息日期；依据：用户陈述。

旧摘要只知道写入日时：

> 记录写入：某日；事件发生时间：未知。

日期字段放在摘要前，不能被正文截断挤掉；时间、来源标签也计入既有上下文预算。证据不够时回答“不确定”，不把“可能”改写成确定日期。

## 后续两阶段

### 第二阶段：时间感知检索

复用现有 recall / 记忆单，区分事件时间与告知时间的查询范围；当前事实与历史事实使用不同模式。先返回短事件卡，需要时再按成员作用域读取少量原文。不得因历史条目已过期就一律排除历史问题的答案。

### 第三阶段：统一上下文预算

统一稳定个人事实、近期对话、按问召回证据的 token 预算；按来源去重，稳定区与变化区分开。硬上限不高于基线，不将截断的事件当作完整证据。此阶段需用相同模型和样例对拍，不预先声称缓存或记忆质量提升。

## 验收矩阵

1. 不同日期说“今天吃了烤肉”，形成不同事件，不折为一条。
2. 本周说“上上周吃过烤肉”，事件时间不是告知时间；下周再问不漂移。
3. 只知道一周范围，不输出未经用户说明的具体星期几。
4. 用户与服务器在不同时区时，依用户指令以记录当时的服务器时区为准；跨午夜、跨月或夏令时切换的范围计算不漂移。
5. 缺少可信原消息时间时，事件时间未知，不能默认填当前日期；服务器时区解析失败明确回退 UTC。
6. 用户明确纠正日期后，旧说法标为被纠正；仅凭两次相似事件不能推断其中一次是纠错。
7. 摘要再次整理后，发生时间、原消息时间、来源与不确定性保持一致。
8. 助手编出的日期和偏好不能晋升为用户确认的事实。
9. 旧无时间记忆读取、召回后仍不增加事件时间字段；被删除的记忆不恢复。
10. 写入失败、伪造来源、跨用户来源与过量证据均拒绝错误关联，不扩大权限。
11. 同一来源消息重试不无限制造重复；不同消息的相同文本不能误当重试。
12. 时间和证据加入后不提高上下文上限；测量正确日期率、错误合并率、无依据日期率、来源命中率与实际 token。

测试先使用合成样例与注入时钟，不读取用户旧记忆、不调用生产模型。涉及模型输出的机制测试使用确定性替身；真实模型评估另行报告费用和覆盖边界。

## 代码边界与实施顺序

1. `personal-memory` 的时间/证据纯函数模块与测试：定义契约、未知值、格式化及校验。
2. `personal-butler` 会话窗、host 可信时间装配：固定服务器时区与来源，测试跨日与来源边界；不新增个人时区配置。
3. `capture.ts` / `agent.ts` / `novelty.ts`：新记录带来源，禁止跨事件误折，测试重试与不同日期。
4. `atomic-facts.ts` / `consolidate-tiered.ts` / `consolidate.ts`：整理来源与用户事实约束，测试多轮整理。
5. `frozen-block.ts` / `toolset.ts` / 记忆单：统一时间标识与预算约束，测试端到端对话样例。
6. 受影响包测试、全仓类型检查、构建、结构门和文档收口；每个独立目标测试通过后单独提交，方向标记为 M。

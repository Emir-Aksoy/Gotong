## 一、命题拆解：用户的三段论到底在主张什么

用户命题可拆成三个独立可检验的断言：

1. **两轴断言**：agent 能力的主干 = 工具使用能力 × 记忆整理与使用能力。
2. **条件化断言**：能力不是绝对量——同一个 agent 骨架，换任务、换底层 LLM（质与量），
   表现完全不同；评测必须把「任务难度」与「所用模型」当自变量而不是背景噪声。
3. **可调节推论**：既然能力是条件化的，优秀 agent 就不该是固定配置，而应具备
   **按任务调整自身配置**（模型、推理强度、成本档位、工具面）的能力。

先给总结论（细节在后文逐节展开）：

- 三段各自都有一线研究强印证。**条件化断言**正是 2024 年《AI Agents That Matter》
  以来「成本控制评测」运动的核心论点；**可调节推论**与模型路由、test-time compute
  可调推理的兴起同向。用户的直觉与前沿方向一致。【证实，见 §四】
- 改进空间集中在三处：**两轴之上还缺哪些轴**（§5.1）；**每轴内部从单点分数升到
  四元组度量**（§5.2）；**「可调节」本身怎么被评测**——评策略而不是评点位（§5.4）。

## 二、一线现状：工具使用能力评测（侦察 A · transcript 抢救 + 主线补核）

### 2.1 主线演化：从「这一次调用对不对」到「这一条工作流走不走得完」【证实】

工具使用评测的演化缩影就是 Berkeley Function Calling Leaderboard（BFCL）自己的版本史
（ICML 2025 论文）：V1 单轮函数调用、AST 结构比对；V2 引入社区真实函数与 relevance
detection（该不该调用）；V3（2024）多轮多步；V4（2025-07）直接把 **web 搜索、记忆读写、
格式敏感性**三块 agentic 能力纳入——格式敏感性用 5 个提示维度组合出 26 种变体，测同一
模型在语义等价输入下的输出稳定性。论文自己的结论：一线模型单轮调用已很强，「记忆、
动态决策、长程推理仍是开放问题」。

同一趋势的更硬形态是 MCP 系基准——对 Gotong 特别直接，这就是我们原生说的协议：

| 基准 | 规模与形状 | 验证方式 | 头部结果 |
| --- | --- | --- | --- |
| MCP-Universe（arXiv:2508.14704） | 11 台真实 MCP server、6 域 231 任务 | 执行态评估器（格式/静态/动态实时取真值） | 长且动态的工作流普遍失守 |
| MCPMark（arXiv:2509.24002） | 5 环境（Notion/GitHub/文件系统/PostgreSQL/Playwright）CRUD 全谱，均值 16.2 轮/17.4 次调用 | 程序化脚本断言（明确拒绝 LLM 判卷），每任务 3–5 专家小时 + 一个月社区复核 | 最好的 gpt-5-medium 仅 52.56% pass@1、33.86% pass^4；claude-sonnet-4/o3 低于 30%/15% |
| LiveMCPBench | 95 任务 | LLM-as-Judge | — |

要点：**当任务变成十几轮的真实 CRUD 工作流，一线模型离「可靠」还差一半以上**——这与
「工具调用已解决」的直觉相反，也解释了为什么骨架层（编排、验收、重试、治理）仍然值钱。

### 2.2 可靠性从平均分里被拆出来：pass^k【证实】

τ-bench（Sierra，arXiv:2406.12045，ICLR 2025）定义 pass^k =「k 次独立运行全部成功」。
原论文里 gpt-4o 在 retail 域 pass^1 约 60%，到 pass^8 掉到约 25%——**best-of-k 掩盖的
一致性崩塌，正是生产环境的真实指标**（用户不会替你重试八次）。MCPMark 跟进同款度量
（最好模型 pass@1 与 pass^4 差约 19 个百分点）。这条一线共识与 §5.2 把「可靠性」从
「质量」里拆出来、§6.4 的链式放大算术直接互证。

### 2.3 用户在环：从噪声变成被测对象【证实】

τ²-bench（arXiv:2506.07982；v1.0.0 2026-07）把评测做成**双控环境**：被测 agent 与用户
模拟器**各自持有自己的工具和政策**，还引入全双工语音实时评测。Apple ToolSandbox 同向
（有状态、对话式、on-policy 用户模拟器）。含义：「与人协同着完成任务」在一线已是主指标
而非附加题——§5.1 轴三（协同能力）不是本篇发明，是把一线已发生的事说破。

### 2.4 敌意输入下的效用：安全与能力合并计分【证实】

AgentDojo（NeurIPS 2024）：97 个真实任务 × 629 个注入用例，**效用与安全联合计分**——
不单测「攻击成功率」，测「攻击在场时任务还能不能完成」。基线数字：GPT-4o 良性效用 69%，
攻击在场掉到约 50%；经典「重要消息」注入的定向攻击成功率约 53%。后续防御能把 ASR 压
数倍到一个量级，但方法论贡献已经立住：**被劫持的 agent，其工具能力是负数**。这正是
§5.1 轴五的计量形态。对 Gotong：治理闸把「攻击成功」结构性转译成「park 卡出现在人面前」，
所以我们的对应指标不是裸 ASR，而是**闸在场时的注入穿透率**——HANDS capstone 幕 1
（注入写配置两层各拒一次、`agents.json` 逐字节不变）已经是这个断言的 demo 形。

### 2.5 验证方式的收敛、代价与第三种量法【证实】

验证方式正从 LLM 判卷向**程序化断言**收敛（MCPMark 明确拒绝 LLM-as-judge；MCP-Universe
用执行态评估器），代价是贵——每任务小时级专家投入花在「造题」上。另有 METR 的第三种
量法：不打分数，量「50% 成功率对应的任务时长」，并报告该时长约每 7 个月翻倍——把能力
表述成「能独立完成多长的活」。对 per-hub 评测的启示：程序化验证贵在造题，而 Gotong 的
`acceptance[]` golden-run 让每个 hub 的真实工作流**自带断言**——题不用造，已经在生产里。

### 2.6 对 Gotong 的直接对应【主张】

| 一线方法 | Gotong 已有件 | EVAL track 缺口 |
| --- | --- | --- |
| pass^k 一致性 | `acceptance[]` golden-run（今天只跑一次 = pass^1） | 同一验收跑 k 次报 pass^k |
| 程序化验证 | `acceptance[]` 断言 + 结构化 checker（`packages/evals`） | 无——形状已对 |
| 效用×安全联合计分 | 治理闸 + HANDS capstone 断言 | 把 demo 断言升级为可重复计量的注入穿透率 |
| 双控/用户在环 | park→人批→续跑本身就是双控协议 | 把「问人问得对不对」纳入计量（轴三） |
| 格式敏感性 | —（工具面 schema 由骨架钉死，暴露面小） | 低优先 |

## 三、一线现状：记忆整理与使用能力评测（侦察 B · transcript 抢救 + 主线补核）

### 3.1 能力分类学已经收敛【证实】

两份互补的分类学基本圈定了「记忆能力」的公认切面：

- **LongMemEval**（arXiv:2410.10813，ICLR 2025）五能力：信息提取、跨会话推理、时间
  推理、知识更新、**弃权**（abstention——知道自己不知道）。500 道人工策展题；商用
  助手在持续交互中记忆准确率掉 30%。
- **MemoryAgentBench**（arXiv:2507.05257）四能力：精确检索、测试时学习、长程理解、
  **选择性遗忘**。结论：「没有一个现行方法四项全能」。

合并去重后的能力面 = **提取 / 跨会话 / 时间 / 更新 / 弃权 / 遗忘** 六项。另一条分界
也已清晰：**长上下文 ≠ 记忆**——把一切塞进百万 token 窗既贵又不解决更新与遗忘，
1M/10M token 档基准（BEAM 一族）的存在理由就是逼系统在「不能全塞」时真做整理。

### 3.2 地基危机：最流行的基准被审计出系统性缺陷【证实】

LoCoMo 是厂商引用最多的长期对话记忆基准，2026-04 的独立审计（locomo-audit）给出的
数字触目：**6.4% 的标准答案本身是错的**（99/1540，且按类别不均匀——open-domain 类错
9.4%）；gpt-4o-mini 判卷器**接受约 63% 的故意错误答案**（模糊答案只要提到正确话题就能
过——恰是弱检索的失败形态）；类别规模差 8.8 倍；**56% 的逐类别系统对比落在统计噪声内**。
第 5 类因缺真值被各厂商共同剔除。含义：记忆评测的地基比工具侧糟得多，公开榜上的分差
大半不可信——这直接支撑 §5.5「不追公共榜」的裁决。

### 3.3 厂商评测战争：同一基准，三家三个数【证实】

- Mem0 论文报 Zep 得分 65.99%；Zep 复测指出三处配置错误（用户角色被建成单人、时间戳
  被拼进消息文本而非专用字段、检索被串行化拉高延迟），更正为 75.14%。
- Letta 用**普通文件系统 + grep/open** 当记忆（gpt-4o-mini），LoCoMo 74.0%，超过当时
  Mem0 图变体的 68.5%；并批评「把记忆工具从完整 agent 系统里隔离出来测，结果没有意义」。
- Mem0 2026-08 博客又报自家 92.5（LoCoMo）/ 94.4（LongMemEval）【厂商自报，无中立复现】。

三条教训：**评测配置本身是战场**；中立复现几乎不存在；记忆必须端到端在 agent 里测。
Letta 的文件系统发现对 Gotong 是直接利好证据：**简单、模型见得多的工具（文件树+检索）
胜过专用记忆栈**——file-first + 管家自管 `knowledge/` md 树（LIB track）正是这个形状，
基质没押错。

### 3.4 写侧评测是集体空白【主张，证据链见文内】

现有基准几乎全部计分在**读侧**（存好之后问得出来吗）；「整理」这半——存什么、蒸馏
质量、何时合并、何时忘——只有三个间接窗口（测试时学习、知识更新、选择性遗忘），
staleness 追踪被行业自己列为未解问题【厂商博客，二手】。把写侧计算移出热路径的
sleep-time compute（arXiv:2504.13171）与 Gotong 的 6h 蒸馏**同构**（离线把 raw context
变 learned context），但其评测形态仍是读侧提问。

这对 Gotong 反而是机会：因为 file-first + 双时态，我们有一批**白盒写侧可测件**是黑盒
记忆服务测不了的——bitemporal close 的正确性、原子事实自包含率、重影率、「忘掉」的
投影同步（HANDS-M7 那条 forget 修复的回归就是现成断言）。这些进 EVAL track 成本近零，
而且是差异化评测面。

### 3.5 对 Gotong 的直接对应【主张】

MU-M1 召回 harness（`packages/personal-memory/src/benchmark.ts` + 棘轮地板）已经是
§5.5 主张的既成雏形：per-hub、零 LLM、recall@k/MRR、只升不降。对照 §3.1 六能力面：

| 能力面 | MU harness 现状 | 扩展动作（岔口 1 内容） |
| --- | --- | --- |
| 提取 / 跨会话 | 已覆盖（keyword/fused/cross-session 类） | — |
| 语义近义 | 已覆盖且诚实（本地天花板 0%，embedder 暂缓已裁决） | — |
| 时间推理 | 未覆盖 | 加时间类 fixture（双时态数据现成） |
| 知识更新 | 间接覆盖（M-RECON 陈旧校正用例） | 升为独立类别 |
| 弃权 | 未覆盖 | 加「答案不存在」类，计误报率 |
| 遗忘 | 未覆盖（机制已建：forgetAll + 投影同步） | 白盒断言进回归门 |

与用户命题的回环：「记忆**整理**和使用能力」这个提法把写侧放进了名字里——一线评测
恰恰是「使用（读侧）」成熟、「整理（写侧）」空白。**用户的轴命名比现行基准更完整**；
Gotong 的结构（file-first、双时态、蒸馏在离线）恰好让写侧白盒可测。

## 四、可调节智能体：评测与实践现状（侦察 C 上半）

> 侦察成色：一手=侦察代理亲自抓取原文；二手=仅见于检索摘要，标注「二手，成色未验」。

### 4.1 成本控制评测运动：用户条件化断言的一线印证【证实】

- **《AI Agents That Matter》**（Kapoor/Narayanan 等，TMLR 2024，arXiv:2407.01502）是
  这条线的起点：榜单只看准确率不看成本，导致 SOTA agent「不必要地复杂且昂贵」；
  最刺痛的实证是在 HumanEval 上「同一模型朴素地多调用几次」就能帕累托支配复杂
  agent 架构。它提出的**成本控制评测**（联合优化成本与准确率）此后成为事实标准动作。
- **HAL（Holistic Agent Leaderboard）**（Princeton，arXiv:2510.11977，ICLR 2026）把这套
  主张基础设施化：21,730 rollouts / 9 模型 × 9 基准 / 约 $40,000 评测费；默认成本控制，
  报「准确率 × 成本」帕累托前沿，全量 trace 公开。三条关键发现：最贵的模型很少落在
  帕累托前沿上；准确率提升常不伴随 token 效率提升；**把厂商推理强度旋钮调高，36 组
  对照中有 21 组准确率反而下降**。

> 最后一条值得单独记住：**「能调」不等于「调高更好」**，而厂商叙事默认后者。这给
> 用户的可调节推论加了一个关键修正——调节必须有证据回路，否则只是换个方式浪费。

### 4.2 模型路由的评测

- **FrugalGPT**（Stanford 2023）：匹配 GPT-4 性能最多省 98% 成本。**RouteLLM**（LMSYS
  2024）：MT-Bench 省 >85% 调用同时保 95% 表现。度量口径=固定质量看成本 / 固定成本
  看质量的帕累托两切法。【证实】
- **商业路由（OpenRouter Auto Router / NotDiamond / Martian）没有一家公开可复现的
  regret-vs-oracle 评测**，全是厂商口径。【证实（缺席本身是一手核实的）】学界正在
  补位（LLMRouterBench、Causal LLM Routing 等，二手未验）；其中《How Much of the
  Routing Gap Is Real?》（二手未验）若成立，意味着 oracle regret 里混入了单次采样
  标签噪声——**路由收益宣传数字被系统性高估**。

### 4.3 「该花多少思考」已成独立评测对象【证实】

- **OptimalThinkingBench**（2025-08，arXiv:2508.13141）：OverthinkingBench（简单题）+
  UnderthinkingBench（难题）双向夹击，指标为 thinking-adjusted accuracy（思考开销折进
  准确率），33 个模型的结论是一句话——**「no model is able to optimally think」**：
  思考型模型在简单题上白烧几百 token 无增益，大号非思考模型在难题上打不过小号思考模型。
- **CostBench**（ACL 2026，arXiv:2511.02734）：多轮成本最优规划 + 动态阻断事件逼迫
  改计划；agent 在静态设定下就常找不到成本最优解，动态下更差。

### 4.4 骨架与模型的分离评测【证实】

「SWE-bench 分数是 harness × 模型的联合产物，榜单只记模型那一半」已被点名（《Stop
Comparing LLM Agents Without Disclosing the Harness》，二手）。量级证据：同一模型换
scaffold 可差 **10–20 个百分点**（Claude Opus 4.5 在 SWE-bench Pro：标准 scaffold 45.9%
vs Claude Code 55.4%，二手；HAL 站点一手口径同向）。应对分三路：锁 harness（HAL）、
统一 scaffold（SWE-bench Pro）、极简 harness（mini-SWE-agent 只给一个 bash 工具）。

> 这正是 §5.3「三元函数拆开测」的一线印证——**骨架增益是真实存在、可达两位数
> 百分点的量**，而它正是框架（而非模型厂商）的产品。

### 4.5 直接回答：「调节策略本身」可测吗——有零件，没整机【证实】

现状：每个可调轴各有评测（模型选择→RouteLLM 曲线；思考多少→OptimalThinkingBench；
动作预算→CostBench；全局→HAL 帕累托），但**没有一个基准把「调节策略 π(任务→配置)」
当作被测对象**。缺的六件：①策略作为被测物的标准协议；②联合动作空间（模型×强度×
scaffold×预算×转派）没人测；③regret 口径不统一且 oracle 被噪声污染；④调节的元成本
（路由器自身 token/延迟/判错返工）不进分母；⑤在线/序贯设定缺失（长任务中途升降档）；
⑥难易分布漂移下的非对称错误代价（把难题误判成简单题 ≫ 反之）无标准测试。

**对 Gotong 的含义**：§5.4 的主张（评策略不评点位）在一线是方向正确但工具缺位——
这恰是自建 per-hub harness（岔口 1）的理由而不是障碍：我们不需要等公共标准，
自家任务上的策略 regret 今天就能量。

## 五、对两轴评价框架的改进意见【主张】

### 5.1 两轴是对的主干——但一个「协作网络里的 agent」还缺三个正交轴

工具使用与记忆确实是单体 agent 能力的两大主干（一个管「对世界做事」，一个管「跨时间
保持连贯」）。但 Gotong 的语境是**人-agent 协作网络**，在这个语境里有三个失败面
两轴盖不住：

- **轴三：协同能力（与人、与其他 agent）**。知道何时该问人、如何把选择摆清楚、如何
  接受纠正、何时转派/求助、被拒绝后如何收场。这不是软技能点缀——τ-bench 一族已把
  「与用户交互着完成任务」作为主指标；Gotong 的治理闸（park → 人批 → 续跑）本质上是
  把这条轴制度化成协议。对协同框架而言，这条轴恰恰是本体。
- **轴四：自知与校准（calibration）**。知道自己不会、不记得、不该动手：工具侧的
  「知道何时不调用」（BFCL 的 relevance detection 一族）、记忆侧的「知道自己不知道」
  （abstention 一族）。**错误的自信比无能更贵**：能力不足损失的是效率，校准不足损失
  的是信任——而信任是协作网络的承重件，重建成本远高于返工成本。
- **轴五：抗操纵（在敌意输入下保持前四轴）**。注入抵抗不是「安全附件」而是能力本身：
  一个被 prompt injection 劫持的 agent，其工具使用能力是**负数**（能力越强破坏越大）。
  这正是 HANDS track 威胁模型「注入即 RCE」的评测面表述（[`ATONG-HANDS.md`](ATONG-HANDS.md)）。

可以把轴四、轴五说成两主轴的「内部维度」，但**建议独立计量**，理由是失败代价不对称：
两主轴的失败是效率损失，轴三四五的失败是信任损失；在网络语境里后者的传播半径大得多。

### 5.2 每轴内部：从「单点分数」升到「四元组」

对每条轴，建议度量四元组：**质量 × 可靠性 × 成本 × 校准**。

- **可靠性单列**（不是质量的注脚）：pass^k 一族指标的动机——一次 90%、复跑 40% 的
  agent，不如一次 80% 但次次 80% 的。数学根源在协作链：可靠性按乘法衰减，三跳各 0.9
  的链路整体只剩 0.73。这直接连到 §七的「低损耗」：**链路质量的地板是每跳的方差，
  不是每跳的均值**。
- **成本进一等指标，且是帕累托不是标量**：只报准确率的榜会系统性奖励堆算力。正确
  形态是「成本-质量平面上的帕累托位置」——这正是用户「不仅计算能力，须考虑 LLM 质与量」
  的规范化表述。【证实，§四有一线印证】
- **校准可以便宜地量**：过度自信率（说做到了而没做到）、拒答正确率（该拒的拒了）。
  Gotong 的审计台账与 acceptance 门天然产生这两个数的原料。

### 5.3 「受任务与 LLM 制约」的操作化：把三元函数拆开测

agent 的真实表现是三元函数 **f(骨架, 模型, 任务)**。评测要有解释力，就要固定其二、
变动其一：

- 同一骨架 × 换模型：测的是骨架的**模型鲁棒性**（弱模型进来还稳不稳）。
- 同一模型 × 换骨架：测的是**骨架增益**——裸模型 vs 进了治理循环/记忆循环之后的差值。
- 同一配置 × 换任务难度桶：测的是**能力边界在哪**（什么任务该转派/升档）。

对 Gotong 的含义很具体：**框架的产品是骨架，模型是用户带来的**。所以框架侧最该测、
也最能自证价值的指标是「骨架增益」——同一个 LLM，裸用 vs 装进 Gotong（记忆蒸馏 +
工具目录 + 治理闸 + 会话窗）后，在同一批任务上的四元组差值。TN-M3 capstone（故意
失忆模型靠笔记本跨轮完成使命）就是这个形状的雏形：它证明的正是「骨架把弱模型托稳」。

### 5.4 「可调节」的评测含义：评的是策略，不是点位

固定配置的 agent 在成本-质量平面上是**一个点**；可调节的 agent 是**一条曲线**（每个
成本档位一个质量）。度量对象因此变了：

- **相对 oracle 的 regret**：如果有全知路由器给每个任务选最优配置，实际策略比它差多少。
- **曲线下面积 / 帕累托支配关系**：可调 agent 应该支配它自己的任何固定配置。
- **调节响应时间**：断供→降级→恢复的时延（Gotong 的 CARE + RoutingProvider 已经在
  量这个：熔断三态、恢复探活 60s 节律）。

一线证据给这条轴加了一个关键修正（§4.1）：HAL 的 36 组对照里 21 组「推理强度调高
反而更差」——**可调节的价值不在「有旋钮」，在「知道往哪拧」**。这把岔口顺序钉死：
先有证据端（岔口 1），再谈调节提案（岔口 2）；没有证据回路的调节只是换个方式浪费。

**Gotong 边界①的约束必须守住**：热路径零 LLM。「现场再叫一个 LLM 判断这条消息该用
哪个模型」撞北极星（[`MODEL-ORCHESTRATION-STRATEGY.md`](MODEL-ORCHESTRATION-STRATEGY.md)
已论证过）。所以 Gotong 语义下的「可调节」=**策略表 + 确定性信号 + 人批变更**：

- 已建成的可调面（全部 file-first、opt-in）：`fallbacks[]` 候选链 + 三态熔断（MR）、
  `thinking` 推理开关（DUO-M4a）、`escalateTo` 双脑转派（DUO）、`maintenanceModel`
  维护低价模型（NA-M5）、EnsembleProvider 并行综合（LSA-M4）、per-candidate
  `apiKeyEnv`（MR-M6）——五个旋钮面 + 三个 provider 组合器，见
  [`packages/core/src/space.ts`](../../packages/core/src/space.ts)。
- 已建成的调节回路模式：RES track 的「探测→提案→人批→应用」——这就是「可调节但不
  自作主张」的 Gotong 形态。
- **缺的是闭环的证据端**：调完之后怎么知道调对了？答案在 5.5。

### 5.5 评测的落地形态：自家任务回归门，不是公共榜

公共基准三病：**饱和**（顶部挤成一团失去分辨力）、**污染**（进了训练集）、**不迁移**
（你的任务不是它的任务）。对一个多租户协作框架，真正有效的评测是**每个 hub 用自己的
真实任务、自己的 LLM 组合，跑自己的回归**。

Gotong 已有这个形态的全部零件，只是没连成一台机器：

| 零件 | 现状 | 缺口 |
|---|---|---|
| 记忆召回基准 | `packages/personal-memory/src/benchmark.ts`，recall@k+MRR，`pnpm check:memory-recall` 棘轮地板只升（MU-M1） | 用的是仓库自带 fixture，不是 hub 自家语料 |
| golden-run 验收 | 模板 `acceptance[]`（FDE-M2），装包即带验收用例 | 只在装包时跑一次，不是持续回归 |
| 结构检查器 | `packages/evals` 纯函数零 LLM（明确不测语义质量） | 语义质量层空缺（刻意的，等需求） |
| 成本账本 | `aggregateLedger` per-user/agent/day 成本聚合 | 成本有了，但没和质量对到同一张表上 |
| 路由健康 | `routing-health.ts` 被动健康 + probe-routing 主动探针 | 只测「通不通」，不测「好不好」 |

**主张**：下一个评测里程碑不是「接入某公共榜」，而是把上表连成 **per-hub 评测
harness**——hub 自家任务集（从真实 run 里策展）+ 四元组度量 + 棘轮地板。它同时是
三件事的证据端：①「可调节」调对了没有；②骨架增益的自证；③§七跨 hub 能力披露的
证据源。（岔口 1，见 §八。）

## 六、跨组织智能体互联：标准与机制现状（侦察 C 下半）

### 6.1 协议分层与治理格局【证实】

一线已收敛成四层：**纵向 MCP**（agent↔工具，2025-12 捐入 Linux Foundation 新设的
Agentic AI Foundation）／**横向 A2A**（跨组织 agent↔agent，LF 独立项目，自报 150+
组织）／**发现层**（AGNTCY OASF「agent 的 DNS」、MIT NANDA AgentFacts、ANP
`did:wba`，互相竞争）／**支付层**（Google+Coinbase AP2 的可验证 mandate、x402 按次
计费）。W3C AI Agent Protocol CG 的规范预期 2026–2027。

两条必须打折读的现实：

- **采用度分层**：logo adoption < SDK adoption < platform adoption < **production
  retention**——所有公开数字停在前三层，「第一次真实运维事故之后仍把 A2A 留在生产里」
  的数据是**空的**（独立分析一手核实）。
- **四套「agent 名片」并存**（A2A Agent Card / AGNTCY OASF / NANDA AgentFacts / ANP
  well-known），其中三套同在 LF 旗下——这是标准层最明显的重复建设，谁收敛无答案。
  Gotong 已对齐的 A2A 卡是其中采用最广的一支，维持现状即可，不追其余三套。

### 6.2 信任机制的阶梯：与 Gotong 判例逐条同构【证实】

- **Signed Agent Card（A2A §8.4）规范原文自己写明**：签名只证「卡未被篡改」，
  **不证明 agent 值得信任**——与 Gotong STD track「签名给完整性不给身份背书」、
  「发现≠信任」逐字同构。
- **A2A 任务状态机含 `INPUT_REQUIRED` / `AUTH_REQUIRED`**：长任务中途挂起等人输入、
  按 task id 续跑——把 human-in-the-loop 写进协议状态机，与 Gotong park→人批→续跑
  同构。这条是跨组织协议里少见的（多数协议把 HITL 留给实现方）。
- 授权：A2A 不发明授权，委托给既有 web 认证（OAuth2/OIDC/mTLS…）。
- **声誉是整个互联生态最弱的一环**：没有任何被广泛采用的跨组织可移植声誉标准，
  冷启动无解（新 agent 到陌生组织一律当陌生人），现有内容以厂商营销为主。

### 6.3 治理鸿沟：协议结构上表达不了的六件事【证实（preprint 一手）】

《Governance Gaps in Agent Interoperability Protocols》（arXiv:2606.31498，2026-07）
逐条列出 MCP/A2A/ACP **结构上表达不了**、且作者判断是「设计取舍而非疏漏」的六件：
**①细粒度授权**（哪个 agent 能做哪个动作）**②委托**（把责任安全转交）**③可追责**
（跨 agent 追溯决策）**④审计轨迹 ⑤撤销 ⑥责任归属**。

> 这张清单对本篇是决定性的：六件里每一件 Gotong 都已经建成（对照表在 §7.3）。
> 一线协议「先做技术互通、把治理留后」的取舍，正是 Gotong 五年反着做的那半边。

### 6.4 协作损耗的实证清单【按证据强度排】

| # | 损耗源 | 证据 | 成色 |
|---|---|---|---|
| 1 | **多轮转手迷路**：多轮比单轮平均掉 39%，拆解为能力 −15% + **不可靠性 +112%**；recap 等常规缓解只补回 15–20%，不及全量拼接 | 《LLMs Get Lost In Multi-Turn Conversation》微软+Salesforce，20 万+对话（arXiv:2505.06120） | 论文级一手 |
| 2 | **MAST 失败分类学**：1,600+ trace / 14 种失败模式 / 三大类——规格与设计 41.8%、agent 间失配 36.9%、验证不足 21.3%；**多数失败源于组织设计而非模型能力** | UC Berkeley（arXiv:2503.13657） | 论文级 |
| 3 | **上下文分裂**：并行子 agent 独立决策互相冲突 | Cognition《Don't Build Multi-Agents》2025-06 | 厂商立场文，与 #2 的 36.9% 互证 |
| 4 | **token 放大**：agent ≈ chat 的 4×，多 agent ≈ 15×；同时多 agent 内部评测 +90.2%（未独立复现） | Anthropic 多 agent 研究系统博客 2025-06 | 厂商自报 |
| 5 | **自然语言当协议本身有损**：采样丢信息、跨轮电话游戏失真 | 多篇（二手未验） | 二手 |
| 6 | **治理信息在协议里没有位置**：授权/撤销/追责只能带外 | §6.3 论文 | 一手 preprint |
| 7 | **对端 harness 不可见**：同模型换 scaffold 差 10–20pp，对端用什么骨架你看不见 | §4.4 | 二手 |

四类归纳：**(i) 上下文型**（#1#3#5）、**(ii) 组织型**（#2）、**(iii) 经济型**（#4）、
**(iv) 治理型**（#6）。**现有互联标准只覆盖 (i) 的传输部分**；「怎么交接上下文才不丢、
这次协作值不值 15× token、委托链怎么表达与撤销」——(ii)(iii)(iv) 全是空白。

### 6.5 两个仍在对撞的问题【证实】

- **多 agent 是否优于单 agent**：Cognition（反）与 Anthropic（正）2025-06 隔天对撞；
  2026 收敛出窄共识=**单 orchestrator 持有连续上下文 + 短命只读子 agent 返回压缩摘要**，
  并行写入型 swarm 因上下文碎片化仍脆弱。MAST 的启示：「多 agent 不行」更多是组织
  设计不成熟，判据尚无人给出。（Gotong 的形态恰在窄共识一侧：hub 路由 + 自包含转派 +
  人批边界，不做并行写入 swarm。）
- **跨组织发现要不要中心点**：NANDA 走「轻量中央索引+组织自有 registry」混合，ANP 走
  纯 P2P + DID。这个未决问题决定「零中央节点」架构会不会被生态边缘化——本篇立场见
  §7.3 末（诚实记录张力，宪章裁决不重开）。

## 七、Gotong 的答案：低损耗高质量互联【主张】

### 7.1 损耗从哪来：五源清单

跨用户 agent 协作的「损耗」不是带宽问题，是以下五源：

1. **上下文转手损耗**（telephone game）：任务在 agent 间转手，背景、约束、验收标准
   一路丢失。
2. **信任重建损耗**：每次协作都要重新证明「我是谁、我能干什么、我上次干得怎样」。
3. **语义错位损耗**：双方对消息形状、能力名、任务状态的理解不一致。
4. **重复劳动损耗**：下游不信上游的产出，重做验证甚至重做工作。
5. **可靠性乘法衰减**：链越长，整体成功率越低（§5.2 的数学）。

这五源与 §6.4 一线实证的四类归纳互相印证（1、3↔上下文型；4、5↔组织型；2↔治理型；
成本边界↔经济型）——**且一线结论是：现有互联标准只覆盖了上下文型的传输部分，
其余全是空白**。空白在哪，差异化就在哪。

### 7.2 已建成的对应件（逐条对到仓库事实）

| 损耗源 | 已建成 | 位置 |
|---|---|---|
| 上下文转手 | 转派必须自包含 `task_summary`（专家看不到对话）；EXCH 信封 fail-closed schema + 未知键拒；工作流 output-ref 链前喂后。一线量化印证：多轮转手平均掉 39%、不可靠性 +112%，全量自包含优于增量 recap（§6.4#1）——自包含单发转手正是论文指出的有效方向 | `personal-butler-escalate.ts` · `exchange-envelope.ts` · workflow resolver |
| 信任重建 | GT 分级信任 T0-T3 + 决策矩阵（信任只降摩擦、永不去底线）；pinnedKid 公钥锚定；签名名片（ES256 JWS + JWKS）；信任引荐不传递 | `core/trust-tier.ts` · STD track · GT-M5 |
| 语义错位 | A2A v1.0 名片对齐；MCP 双向；MESH 公开 wire 规范；「协议不降级只降传输」（EXCH 立场） | `MESH-PROTOCOL.md` · `EXCHANGE-ENVELOPE.md` |
| 重复劳动 | 幂等 id（信封/绑定码）；outbox 补投保序；审计台账（谁批的、经哪个渠道） | EXCH-M1 · CARE-M8 · IMA-M2 |
| 可靠性衰减 | 出站审批闸=边界验收点；配额 fail-closed；熔断+failover 把单跳方差压低 | outbound-approval · MR track |
| 成本边界 | 计费各归各家（每 hub 自己的 key 自己的账本）；用量账本按人按天聚合 | 北极星第 2 层 · `ledger-store.ts` |

这张表说明：Gotong 五年积累的治理面，恰好就是「低损耗互联」的基础设施——**治理闸
不是摩擦，是把信任变成可复用资产的机制**。

**外部印证（决定性的一条）**：§6.3 那篇治理鸿沟论文列出的六件「MCP/A2A/ACP 结构上
表达不了的事」，逐条对到 Gotong 已建成件：

| 治理鸿沟（arXiv:2606.31498，2026-07） | Gotong 已建成 |
|---|---|
| ①细粒度授权（哪个 agent 能做哪个动作） | outboundCaps 白名单 fail-closed + 能力策展（advertise=authorize）+ HANDS 四档表 |
| ②委托（把责任安全转交） | escalateTo 转派（自包含 task_summary）+ 工作流 assignee 路由 + 收件箱 delegate（代际闸防掉包） |
| ③可追责（跨 agent 追溯决策） | 审计台账 actorSource/metadata.via（谁批的、经哪个渠道）+ 跨 hub origin 真章 executedBy |
| ④审计轨迹 | file-first transcript + jsonl 审计（0600、轮转阈值推导自台账容量）+ 用量账本 |
| ⑤撤销 | peer disabled/revoked 边即时剔除 + 凭证 revoke 即断数据面 + IM 解绑/设备断开 |
| ⑥责任归属 | 治理闸=后果动作人点头且批准者留名 + 分级信任 dangerous 恒 member_notify（信任降摩擦、永不去追责底线） |

这不是巧合。「先做技术互通、把治理留后」是一线协议作者自认的设计取舍（§6.3），
Gotong 反着做的正是这半边。**跨组织协作的竞争差异不在管道层（那里在收敛且拥挤——
四套名片标准打架），在治理层（那里六件全空白）**。【主张】

### 7.3 缺的一块：能力声明没有「证据」维度

现在的能力披露是**自报**（A2A 名片 advertise）+ **人工分档**（GT 信任档 owner 拍板）。
中间缺一层：**能力声明的可验证证据**。

**主张：「评测过的能力才是能力」**。能力披露应可以携带证据——可复跑的 golden-run
用例、签名的评测结果摘要、成本区间——让对端不必从零验证。形态上：

- 证据 = {任务集指纹, 四元组结果, 运行时间, 签名}，评测用例本身随证据发布（对端可
  独立复跑——这是防 Goodhart 的结构性手段：不可复验的分数不算证据）。
- **证据是 advisory，永不自动升信任档**。GT 铁律「声明≠信任」原样延伸：证据是声明
  的一种更强形态，升档仍然人点头。软连接（建议卡）而非硬连接。
- **零中央节点约束**：不建声誉中心、不建评分目录。证据点对点签名传递 + 本地台账，
  与 GT-M4「纯软连接」同构。这是与代币/中央注册表路线的分野（宪章已裁决不重开）。

### 7.4 低损耗的第一性原理：让证据随工作产物旅行

把 7.2 + 7.3 收成一句话：**跨组织协作的损耗，本质是「证据不随工作产物旅行」的税**。
背景丢了要重问（损耗 1）、身份忘了要重证（损耗 2）、含义歪了要重对（损耗 3）、质量
疑了要重验（损耗 4）。Gotong 的路线因此不是「更快的管道」，而是**更完整的信封**：

> 一件跨 hub 交付物 = 产出本体 + 验收标准（它该满足什么）+ 出处链（谁在什么授权下
> 做的，`executedBy`/origin 真章已有）+ 质量证据（哪些验收过了）+ 签名（不可抵赖）。

收到这样一个信封的下游，验收成本从「重做」降到「复核」，信任成本从「重建」降到
「验签」。这就是「低损耗高质量」的机制化表述。

### 7.5 「人-agent 关系」层的回答

用户把命题上升到「人类与智能体的关系和未来」。Gotong 宪章已有立场：**人和 agent 是
同一个 Participant**，治理闸把「后果落在人身上的动作」留给人点头。评测框架的对应
推论：

- 单体 agent 的分数不是终点。**协作网络的度量单位应从「单 agent 能力」走向「网络
  增益」**：加入这个 agent 后，整个「人+agent 网络」的产出质量/成本/可靠性变好了
  多少。一个分数很高但让全网络返工的 agent 是负资产。 MAST 的结论——多数
  多 agent 失败源于组织设计而非模型能力（§6.4#2）——从反面支持这一点：**网络的
  质量主要由组织设计决定，而组织设计正是框架的产品面**。
- 「可调节」的最高档不是自动化，而是**自治程度本身可调**（该问人的问人，被授权的
  自己跑）——分级信任对 agent 网络如此（GT），分级自治对自己的 agent 亦然（HANDS
  四档表就是自治分级的实例）。人的角色不是被替代的操作员，而是**信任的最终签发者**。

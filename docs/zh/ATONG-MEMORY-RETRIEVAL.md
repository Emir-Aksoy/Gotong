# 阿同的证据优先记忆

方向：M。2026-09-21 开发分支实现；尚未推送或部署。

## 设计

借鉴的是“先想起线索，再回忆细节”，不是模拟一个新的人脑系统。既有文件仍是真相源：

1. 对话原文保存经历和原始时间；已有的整理链选择用户证据并保留原话。
2. 冻结块保留小份常用记忆，沿用原有默认 4000 字符上限。
3. 自动记忆单按当前问题跨记忆、知识文件、任务本及长任务档案找线索。
4. `search_memory` 返回短线索和来源 `id/revision`；`read_memory` 重新读取来源后核对版本，再分段返回必要内容。
5. 证据不足时说明不确定，不把相关性分数解释为事实置信度。

没有新数据库、新记忆层、新 LLM 规划器或新环境变量。Gotong 仍负责隔离、路由和治理；检索与整理属于 agent 侧。

## 时间和真实性

- `recorded` / `recordedAt` 是记录时间，不是事件发生时间。
- 原始 `turn-start`、服务器时区、原话中的已锚定日期范围会随证据呈现。没有事件日期就不编日期。
- 默认检索只取当前有效的事实；失效记录在种子截断之前排除，不能抢占有效记录的位置。
- `recall` 支持 `history: true` 和 `asOf`。后者筛选事实有效区间，不是“事件发生于某日”的过滤器。历史结果明确显示有效区间。
- `search_memory` 可用 `stores` 限定来源；时间问题查 memory，进度查 task/dossier，资料查 knowledge，操作经验用 `recall` 的 `form: procedure`。
- 原生 Atong 的 `remember` 要求完整、逐字一致的用户证据。当前轮原话由执行上下文提供；旧证据通过当前用户的索引读取。模型自己的回复、改写，以及自报 `confirmed: true` 都不能充当用户确认。
- 新任务挂起时保存原时间锚及任务/成员/原话的哈希绑定，审批恢复后重建原始证据作用域，不把批准回复当作新事实。旧恢复状态没有可信原时间时，不重新制造一个“当前用户原话”来源；仍可引用已有可验证来源。旧记录不批量回填、不自动改写。

## 上下文预算

自动记忆单、`recall`、`search_memory`、`read_memory` 在原生 Atong 中共用每次执行 6000 UTF-8 字节的动态记忆预算，单次最多 2000 字节。预算在异步任务作用域中隔离，同一任务内嵌套工具不会重置预算。

这个数不是“整个模型上下文”的上限：既有冻结块、对话窗、任务本提示和其他工具结果继续使用各自已有约束；固定错误提示不计入证据负载。暂停后的恢复执行重新建立读取预算，不宣称跨多次恢复的终身总额封顶。

自动记忆单跳过同源证据的重复副本。`recall` 不重复返回本次执行已经返回的记录；`read_memory` 不重复返回同一版本同一偏移片段。读取不足一页时返回 `nextOffset`，不把片段伪装成全文。尚不做跨冻结块、对话窗、所有工具结果的全局语义去重。

## 存储整理

- 文件后端新增显式 `scan()`，复用同一用户的严格快照与读写排队。完整导出、预算核算、原子事实去重、降温和临时输出清理使用全量读取；交互式 `list()` 仍最多 500 条。
- 不支持 `scan()` 的替代后端会拒绝这些维护操作，不能以可能截断的 `list()` 静默替代。第三方后端需实现此能力后再开启维护。
- 降温只写 `cooledAt`，改变存储回收优先级，不再写事实失效时间 `validTo`。低频不代表不真实；实际容量不足时仍由既有预算执行器逐出。
- 旧版本已写入的 `validTo` 不自动清除，因为无法可靠区分真正过期与历史降温。

## 读取边界

来源标识不是文件路径权限或授权令牌。只能在工厂提供的当前用户记忆空间内解析；不接受任意磁盘文件访问。版本标识是内容身份校验，读取时来源变化、删除、隔离或重新读取失败都会拒绝返回旧证据。

自动搜索沿用最长 60 秒的派生网缓存；显式读取绕过缓存且失败不回退旧网。当前实现显式读取会重新列举已接入的来源，优先保证一致性，不声称是常数时间的单文件读取。沿用既有范围：生产未把历史会话窗作为独立全量库接入，长任务最多列举近期 20 份档案及每份 100 条尾部记录。

本轮未接通先前暂停的硬删除/纠正入口，没有迁移或删除真实用户记忆。真实模型的回答质量仍需上线后用用户案例验证，自动化回归不等同于“永远不会记错”。

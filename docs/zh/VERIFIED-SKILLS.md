# 可验证的个人经验技能

方向: **M+T**。Atong 是 Gotong 网络的原生 agent；本项先增强阿同个人经验的复用质量，不把模型决策放进 Hub，也不自动共享个人记忆。

## 从经验到发布

1. `remember_procedure` 保存候选。除名称和步骤外，必须提供个人记忆中的来源 ID、适用条件与反例。
2. `approve_procedure_tests` 提交输入和明确预期输出，在现有 `/me` 收件箱由用户确认。模型生成的答案不是独立验收标准；请提供自己认可的保留案例。
3. `verify_procedure` 让同一个明确标识的模型分别运行已发布基线与候选。第一次的基线是不带技能的模型。执行器看不到预期答案，没有工具、文件访问或外部动作；服务端以实际完整输出做精确比较。
4. `publish_procedure` 只发布当前版本通过当前测试集的证据。候选全部通过才有资格发布；这意味着在这些案例上不低于基线，不意味着一定优于基线。
5. `refine_procedure` 增加新的未测试版本，旧发布版本不被悄悄替换。`rollback_procedure` 恢复上一个已通过的发布版本；`inspect_procedure` 查看版本、证据与当前状态。

可对阿同说：

> 把刚才处理任务的经验保存为候选技能，注明来源、适用条件和不适用的反例。先不要发布。我会给出独立的测试输入与预期答案，你把它们送到收件箱让我确认，再测试并报告候选和基线的实际结果。

工具名称是稳定入口，自然语言能否一次正确完成取决于所用模型。没有启用治理入口时不能批准测试；没有明确可识别的评测模型时拒绝评测，不猜默认模型。

## 证据的边界

- 证据锁定技能版本、内容指纹、测试集指纹、模型标识，以及双臂的实际输出。没有接受外部 `passed` 的接口。
- 成功范围始终为 `sandbox-output-only`。本版验证文本输出，不验证实际 MCP 调用、网页操作、邮件送达或真实业务效果；发布技能不会增加工具权限，也不会绕过原审批。
- 预期输出采用精确字符串比较，空白也有意义。不使用另一个模型打一个模糊的“合格分”。
- 用户确认标准不等于数学上消除了测试泄漏；请勿把训练案例原样当作保留案例。少量通过案例不能证明通用能力提升。
- 自动提炼与合并只生成候选；旧技能仍能阅读并标为未验证，不自动进入已发布步骤的提示词投影。

## 文件与运行

版本、测试集和证据复用现有个人 `MemoryEntry.meta.skill`，随个人记忆目录一起迁移；`SKILL.md` 仍是可重建投影，不是另一份真相。保留案例也是个人数据，适用现有导出、遗忘与访问边界。

单技能最多 16 个版本、8 份测试集、16 份评测，元数据最多 512 KiB；每份测试集最多 8 对输入/预期。生产审批要求完整参数 JSON 在 900 字符内且能原样显示，超限应缩短案例，不会截断后让用户盲批。达到存储上限会拒绝继续追加，不会为腾空间悄悄丢掉版本历史。

双臂的每次模型调用都走既有个人/组织配额检查与费用记录。模型中断、超时、空输出、已配置记账但供应商未报告用量，或评测期间发生内容漂移时均不能发布；账本持久化的故障处理沿用现有机制。技能进入冻结块时，步骤、条件和反例作为整体保留；超出提示词预算则整体省略，不只删掉限制条件。

## 验证入口

- `packages/personal-memory/tests/verified-skills.test.ts`：状态机、失败证据、版本与测试集漂移、回滚、边界和工具参数。
- `packages/host/tests/personal-butler-verified-skills.test.ts`：真实治理挂起/批准/拒绝恢复、模型执行路径、文件重开与个人隔离。
- 冻结块和技能投影回归：未验证步骤不能冒充已发布步骤；已有发布保持可用。

本轮不包含跨 Hub 技能分发、后台自动发布或真实工具沙箱评测。

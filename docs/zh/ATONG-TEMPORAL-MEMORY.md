# Atong 时间记忆

方向: M。M1 与 M2 的来源保真、原话事实整理已本地实现并验证，未发布、未部署。
M2 的事件日期归一化与 M3 仍待实现，不能把这次阶段收口理解为整个时间记忆计划完成。

## 时间口径

采用服务器时区，不猜测用户所在地。每条新对话固定保存当时解析出的 IANA 时区；
无法解析时明确保存 UTC。服务器以后更换时区，不会重新解释已有时间锚。

- `meta.temporal.observedAt`：本地 agent 开始处理新任务的时间，不是外部渠道原始发送时间。
- `meta.temporal.timeZone`：这次新任务观察时的服务器时区。
- `meta.temporal.basis = turn-start`：明确说明上述依据。
- `MemoryEntry.ts`：记忆写入时间，召回时明确标为 `recorded`。
- 事件发生时间：M1 不提取、不推断，显示 `event-time: unspecified`；不能把告知日当成发生日。

会话窗的新消息也保存服务器时区，并在送给模型的历史正文前显示时间标签。
标签与正文一起计入原有长度限制；同角色消息合并时保留各条原有标签。

## 已实现边界

1. 在模型工作开始前固定时间，长回复跨午夜不改变原任务时间锚。
2. 静态附加 metadata 与任务 payload 不能冒充受信任的本地时钟。
3. 没有持久化原时间锚的恢复任务不编造原消息时间；底层恢复失败而重跑时只捕获一次。
4. 带新时间锚的轮次不按字面相似度折叠。无锚调用也不能折入带锚记录；旧无锚路径保留原新颖门。
5. 冻结记忆块显示时间标签，标签计入既有正文预算。放不下时整条省略，不裁掉日期后继续冒充完整证据。
6. 不运行历史数据迁移，不恢复已删除或丢失的记忆，不给旧条目补日期。

**取舍**：新对话暂时会保留更多独立记录。原有存储预算和逐出机制仍有效，
这并非降低了存储量；旧新颖门基准的节省数字不能作为新时间链路的成绩。
冻结块与会话窗限长未提高；recall 的跨模块统一 token 预算仍待 M3。

  本轮来源保真不等于已经推断事件发生日期。
- **M3**：按事件时间/告知时间检索、历史问题召回，跨提示词区块按来源去重并统一固定 token 预算。

因此，M1 证明的是时间记录与呈现链路，不是“所有日期问题都能正确回答”。

## M2 来源保真

新对话在捕获时记录用户正文的精确位置，不靠解析正文里的 `User:` / `Butler:` 标签。
保留用户原文的换行和缩进，避免把分行日期与事件压平后改变对应关系。
这是**对话角色来源**，不是新增的身份认证机制；成员与机构隔离仍由宿主的既有授权边界负责。
截断过的用户正文不会作为完整事实晋升，旧记录缺少位置证据时不推测补齐。

普通整理、分层整理、摘要晋升遇到新证据时采用保留原话的路径：

- 派生正文只保存用户原话；元数据记录原始来源 ID、原话位置与原时间锚，不重复保存整份原话。
- 一条派生记忆至多含 8 个原始来源。正文和元数据一起计入既有整理上限；超限留源，不截断证据。
- 写入返回的记录须通过证据一致性检查，之后才删除已完整保留的来源。低重要度不是跳过此检查的理由。
- 同一来源 ID 若出现不同内容、时间或成员作用域，不能静默选择其中一个。
- `userId` / `user` 两个既有作用域字段若矛盾或类型错误，拒绝读取、打包及写后验证。
- 冻结块与 recall 显示原始引用和原时间，不把新摘要的写入时间当成事件时间。
- 旧自由改写式 reconcile 不能更新或删除这些证据；用户显式遗忘与既有存储保留政策不受影响。

来源 ID 指向**原始来源身份**；原始记录整理后可能已删除，派生记录保留的是原话证据，
不代表原记录仍可按 ID 读取。没有新增读取其它空间或备份的能力。

原子事实整理也改为由模型选择来源 ID，而不是接受模型自由生成的事实正文。
实际保存的是选中来源的完整用户原话。即使模型误选了“上周买过一杯奶茶”，
也不能把它写成“用户最爱的饮料是奶茶”。缺少结构化来源的旧混合对话不进入这条自动提炼链。
来源编号相同必须再核对原文、时间和归属；冲突在写入前报告给现有维护健康链，不覆盖旧记录。

**取舍**：这是保守的原话整理，不是任意自然语言语义压缩。会减少助手回复和重复原文的占用，
但并不保证每条短记忆都更小；仍保留旧存储预算，未扩大提示词上限，也没有宣称新的同义词召回提升。
新证据暂用确定性关键词分类与已有重要度，不再由模型在改写摘要时推断分类和评分；
旧无结构记录的模型整理路径仍保留。来源保真与未来更精准的分类是两个不同的验收项。

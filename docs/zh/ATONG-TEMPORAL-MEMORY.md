# Atong 时间记忆

方向: M。M1 与 M2 的来源保真、原话事实整理已本地实现并验证，未发布、未部署。
M2 新增有界日期词解释、纠正底座与内部文件提交；用户纠正入口、完整硬删除收尾与 M3 仍待实现，不能把阶段收口理解为整个时间记忆计划完成。

## 时间口径

采用服务器时区，不猜测用户所在地。每条新对话固定保存当时解析出的 IANA 时区；
无法解析时明确保存 UTC。服务器以后更换时区，不会重新解释已有时间锚。

- `meta.temporal.observedAt`：本地 agent 开始处理新任务的时间，不是外部渠道原始发送时间。
- `meta.temporal.timeZone`：这次新任务观察时的服务器时区。
- `meta.temporal.basis = turn-start`：明确说明上述依据。
- `MemoryEntry.ts`：记忆写入时间，召回时明确标为 `recorded`。
- 事件发生时间：M1 不提取、不推断，显示 `event-time: unspecified`；不能把告知日当成发生日。

会话窗的新消息也保存服务器时区，并在送给模型的历史正文前显示时间标签。
标签与正文一起计入原有长度限制；同角色消息合并时保留各条原有标签。

## 已实现边界

1. 在模型工作开始前固定时间，长回复跨午夜不改变原任务时间锚。
2. 静态附加 metadata 与任务 payload 不能冒充受信任的本地时钟。
3. 没有持久化原时间锚的恢复任务不编造原消息时间；底层恢复失败而重跑时只捕获一次。
4. 带新时间锚的轮次不按字面相似度折叠。无锚调用也不能折入带锚记录；旧无锚路径保留原新颖门。
5. 冻结记忆块显示时间标签，标签计入既有正文预算。放不下时整条省略，不裁掉日期后继续冒充完整证据。
6. 不运行历史数据迁移，不恢复已删除或丢失的记忆，不给旧条目补日期。

**取舍**：新对话暂时会保留更多独立记录。原有存储预算和逐出机制仍有效，
这并非降低了存储量；旧新颖门基准的节省数字不能作为新时间链路的成绩。
冻结块与会话窗限长未提高；recall 的跨模块统一 token 预算仍待 M3。

## 尚未完成

- **M2 后续**：将日期词与具体事件可靠关联、明确纠正关系及复杂转述中的时间参照。
  已实现的日期词解释不等于自动确认事件发生日期。
- **硬删除收尾**：文件层已有版本核对、旧句柄屏障与失败恢复；仍需索引/投影/快照清理、
  存活及暂停会话上下文退役，以及可信用户纠正意图接线。当前 `forget`/`forgetAll` 不能被当成完整链路。
- **M3**：按事件时间/告知时间检索、历史问题召回，跨提示词区块按来源去重并统一固定 token 预算。

因此，M1 证明的是时间记录与呈现链路，不是“所有日期问题都能正确回答”。
未调用真实模型评测，也未读取用户历史对话；测试用合成文本与注入时钟。

## M2 来源保真

新对话在捕获时记录用户正文的精确位置，不靠解析正文里的 `User:` / `Butler:` 标签。
保留用户原文的换行和缩进，避免把分行日期与事件压平后改变对应关系。
这是**对话角色来源**，不是新增的身份认证机制；成员与机构隔离仍由宿主的既有授权边界负责。
截断过的用户正文不会作为完整事实晋升，旧记录缺少位置证据时不推测补齐。

普通整理、分层整理、摘要晋升遇到新证据时采用保留原话的路径：

- 派生正文只保存用户原话；元数据记录原始来源 ID、原话位置与原时间锚，不重复保存整份原话。
- 一条派生记忆至多含 8 个原始来源。正文和元数据一起计入既有整理上限；超限留源，不截断证据。
- 写入返回的记录须通过证据一致性检查，之后才删除已完整保留的来源。低重要度不是跳过此检查的理由。
- 同一来源 ID 若出现不同内容、时间或成员作用域，不能静默选择其中一个。
- `userId` / `user` 两个既有作用域字段若矛盾或类型错误，拒绝读取、打包及写后验证。
- 冻结块与 recall 显示原始引用和原时间，不把新摘要的写入时间当成事件时间。
- 旧自由改写式 reconcile 不能更新或删除这些证据；用户显式遗忘与既有存储保留政策不受影响。

来源 ID 指向**原始来源身份**；原始记录整理后可能已删除，派生记录保留的是原话证据，
不代表原记录仍可按 ID 读取。没有新增读取其它空间或备份的能力。

原子事实整理也改为由模型选择来源 ID，而不是接受模型自由生成的事实正文。
实际保存的是选中来源的完整用户原话。即使模型误选了“上周买过一杯奶茶”，
也不能把它写成“用户最爱的饮料是奶茶”。缺少结构化来源的旧混合对话不进入这条自动提炼链。
来源编号相同必须再核对原文、时间和归属；冲突在写入前报告给现有维护健康链，不覆盖旧记录。

**取舍**：这是保守的原话整理，不是任意自然语言语义压缩。会减少助手回复和重复原文的占用，
但并不保证每条短记忆都更小；仍保留旧存储预算，未扩大提示词上限，也没有宣称新的同义词召回提升。
新证据暂用确定性关键词分类与已有重要度，不再由模型在改写摘要时推断分类和评分；
旧无结构记录的模型整理路径仍保留。来源保真与未来更精准的分类是两个不同的验收项。

## M2 日期词解释

新捕获通过 `meta.calendar` 保存版本化的原话位置和本地日历范围，整理时随每个来源保留。
支持：今天、昨天、前天、明天、后天；本周、这周、上周、上上周、下周、下下周；
明确的 `YYYY-MM-DD` / `YYYY年M月D日`。不使用模型、外部服务或新的配置项。

- 相对日期锚定原任务的服务器本地日期，周按周一开始、下周一结束的半开区间保存。
  例如服务器日期 2026-09-11 时的“上上周”为 `[2026-08-24, 2026-08-31)`，即 8 月 24 日至 30 日。
- 日历日期不是 UTC 时刻，未编造每天几点发生；跨午夜、闰日、跨年、夏令时不靠本地 24 小时加减。
- 缺少可信时间锚的相对词保持未知，非法日期不滚入下个月；缺年日期、上周三/周末等未支持表达不擅自补精度。
- “去年今天”“上周的今天”等已知复合参照，以及“后天性疾病”等非日期词保守跳过，避免截取其中两个字误算。
- 每段原话最多四个日期词，超出明确标注省略；正文、日期和来源元数据继续计入既有整理上限。
- 读取只验证已有版本和原时间锚，不给旧条目生成日期字段。后来的系统时间和进程时区不参与重新锚定。
- 召回和冻结上下文显示日期解释，避免重复输出同一告知时间；放不下仍整条省略，不扩大预算。

**重要边界**：这是“日期词按原告知日解释”的记录，不是自然语言事件解析器。
问句、否定、假设、引文、转述仍保留原话，并标明 `not event claims`；不得仅凭这个范围断言事情发生。
例如“昨天他说上周”的内部参照或“上周左右”的模糊事件范围尚未求解，不能把字面日期范围当最终事件日期。
没有自动关联两条相似陈述，也没有通过新记忆覆盖旧事件。真实模型答对日期的比例需要后续独立评测。

## M2 纠正底座

**用户确认的行为**：明确纠正且旧来源唯一时直接替换，不额外确认；被纠正内容及相关受管副本硬删除，
不保留旧版本。只在目标含糊时询问，不因描述相似而删记忆。不进行历史批量迁移、补写或恢复。

本阶段只实现两项底层能力，**尚未接入对话或删除任何真实记忆**：

1. 文件后端 `snapshot()` 在同一用户的进程内写队列中完整读取已配置种类，不受交互列表 500 条上限影响。
   原字节指纹用于后续写入前核对；损坏内容、非普通文件、越界链接和读取错误明确失败，不返回部分结果。
   `list` / `recall` 上限未改变，旧预算和导出调用也尚未改用快照，不能据此宣称它们的全量问题已经修复。
2. `prepareEvidenceCorrection()` 只计算结构化来源的变更：精确完整原话匹配，同一来源多份副本一并定位，
   不同来源同一句话须消歧。混合容器仅重打包其它来源的原文、时间和日历信息，不继承旧聚合元数据；
   新用户陈述单独保存为 semantic 候选，使用本次纠正的时间锚和新的来源 ID。

来源冲突、坏证据和 packed/raw 双表示不静默裁决；合法但没有用户来源的助手记录与旧无结构记录列为
`untraced`，不能凭字符串相似就删除。计算器不识别任意自然语言纠正意图，也不承担成员鉴权。
输入必须来自完整、已授权的单用户快照；返回 `ready` **仅表示可计算，不表示已授权、已落盘或已彻底删除**。
字节上限仍生效，超限整次拒绝，不截断无关来源以腾位置。
重建条目补齐原编号和写入时间后复验完整字节数；新条目仍是待保存载荷，执行器生成编号/写入时间后还须核预算。

完整执行器必须在落盘前重核快照并处理未追踪派生内容、索引、Git 历史和会话缓存，不能让旧维护任务重新写回。
完整快照也不是跨进程事务；应用外部备份和操作系统快照不属于可承诺清除的范围，历史备份目录不触碰。

## M2 内部文件提交

`MemoryFileHandle.applySnapshotMutation()` 在同一 owner 队列内重核完整快照，批量删除、重建和追加。
快照指纹绑定 owner、配置种类、文件原字节与持久化代际。目标不存在、重复编号、过期版本、非法载荷或
完整条目/种类文件超限均在修改主文件前拒绝；不截断无关记忆来腾出空间，未修改的行保留原字节。

- 恢复记录只含修改后内容及前后指纹，不建立旧文件备份。先同步并发布恢复记录，再原子替换各主文件。
- 多文件替换不是文件系统级原子事务：中断后阻止受管句柄普通读写，可信宿主显式调用 `recoverMutation()`。
  恢复先核验所有受影响文件均处于预期的修改前/后状态，再统一向前完成；未知漂移拒绝覆盖，不回滚旧原文。
- 临时后像按事务代际及固定种类命名，恢复前检查并清理已验证残留。未知归属、损坏或部分写入的临时文件
  保守阻断，不通配删除。清理完成并同步后，最后解除 pending 标记；此后没有可能返回失败的文件操作。
  标记删除不承诺掉电持久化，重启可能再次要求恢复；代际已是修改后时，只有全部后像匹配才接受，防止覆盖后续写入。
- 正常读写过的句柄固定所属代际；纠正成功后，旧句柄的读写均失败，不静默重开。
  成功提交的句柄、新建句柄，以及完成显式恢复的可信调用方可使用新代际。
- 新增内部 `correctButlerMemoryFiles()` 自行按可信 userId 开库、计算方案、拒绝未追踪记录并提交。
  输入在异步读取前复制，调用方附带的 userId 不能覆盖宿主作用域；结果只叫 `memory_files_updated`。

**尚未连接 Web、对话或模型工具，也没有对用户真实记忆执行纠正。** 文件屏障不覆盖直接读取 JSONL 的索引、
已经构建的提示词或第三方进程。下一阶段必须在宿主按用户隔离期间清理派生内容、退役旧执行，完成后才能开放入口：

- recall-index 的内存及磁盘副本、进行中的刷新，以及 memory-net 的 TTL/失败回退缓存。
- 维护、Obsidian 投影、DREAMS/SKILL/STATUS 和 Git 快照；Git 还须明确排除事务内部文件。
- router 的用户实例、记忆服务的旧句柄、IM/Web 会话窗、暂停任务及迟到回复。
  群聊窗口涉及其他成员，不能按单用户目录直接粗暴清空。

不新增跨进程锁，不承诺物理介质安全擦除，不触碰应用外部备份；完整协调期间的隔离不能随文件 journal 消失就解除。

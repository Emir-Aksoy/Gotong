# Gotong 三大方向 — 开发规划钉子

> Status: **活文档 · 2026-08-21 用户钉死**。本文回答两件事:我们往哪三个方向走,
> 以及「每一个开发都要说明增强哪个方向」这条纪律怎么执行。
>
> 修订规则:三大方向本身与开发纪律条款 = 用户拍板才能改;各方向的现状/路线小节
> 随开发滚动更新(每次收口顺手补账)。

---

## 一、三大方向

我们未来聚焦的三大方向。之后的每一个开发都往这三个方向走:

### T — 工具调用能力

让 agent 把工具**用对、用省、用安全**。覆盖:工具循环的形状、工具面的组织与
裁剪、执行分级与沙箱、调用韧性(超时/重试/熔断/降级)、调用效果的度量与回路。

为什么是它:agent 的能力一半在工具使用。工具用不对 = 幻觉出手;用不省 = token
烧在 schema 上;用不安全 = 注入即事故。一线评测(τ-bench pass^k、MCPMark)证明
多步工具工作流远未解决——**骨架仍值钱**,这正是 harness 层的用武之地。

### M — 记忆管理能力

让 agent 把记忆**整理好、用得上、忘得掉**。覆盖:捕获与蒸馏、检索质量、
分层组织(进货区/上架区/索引)、双时态与遗忘、投影(给人看的面)、跨会话连续性、
记忆侧的可测性。

为什么是它:agent 能力的另一半在「记忆整理与使用」——注意是**整理**,不只是
检索命中。业界评测几乎只测读侧(提取/跨会话/时间推理),**写侧(整理质量)是
集体空白**,而我们 file-first 白盒架构恰好可测——这是差异化面,不是跟跑面。

### C — agent 间协作框架

让不同人的、不同宿主的、不同信任层级的 agent **低损耗、高质量地互联协同**。
覆盖:跨 hub 联邦与信任分级、互操作协议面(A2A/MCP/信封/技能包)、治理随协作
旅行(授权/委托/可追责/审计/撤销/责任归属)、协作损耗的度量与压低。

为什么是它:这是 Gotong 作为**框架**的存在理由。标准协议(MCP/A2A)只解决
连得上,治理鸿沟六件(细粒度授权/委托/可追责/审计/撤销/责任归属)协议表达不了
——我们六件全建成,竞争差异就在治理层。协作的失败代价不对称:能力失败损失
效率,**信任失败损失网络半径**。

## 二、方向(域)× 方法论(法):与既有定调的关系

CHARTER §5 已钉的「LLM 自适应 × 形态兼容 × 能力搬家」(2026-08 定调,出处
STRATEGY-2026-08 §十)**不是被替代,而是换了一个轴**:

- **三大方向是聚焦域**——回答「提升什么」(工具 / 记忆 / 协作)。
- **既有定调是方法论**——回答「怎么提升」(同一副骨架适应任意档 LLM /
  到对方已在的形态去 / 把能力从权重搬进可携带结构)。

两轴正交:每个开发落在**一个主聚焦域**上,同时可以用任意几条方法论。例:
EXCH-M5 gotong-client 包 = 域 C(协作) × 法「形态兼容」;EFF 效果回路 =
域 T(工具) × 法「LLM 自适应」的证据端;LIB 图书馆员 = 域 M(记忆) ×
法「能力搬家」(知识从上下文搬进书架)。

## 三、开发纪律(钉死)

> **之后每一个开发都要说明增强的是哪个方向。**(2026-08-21 用户令,原文钉此)

执行方式(三处落点,一个格式):

1. **开工时**:任务规划的第一句话说明主攻方向(「本刀主攻 T,顺带 C」)。
   说不出增强哪个方向的新功能,先回到「为什么要做」——方向说明是立项判据,
   不是事后贴纸。
2. **commit message**:body 里带一行方向标注(见下)。
3. **CLAUDE.md 账本条目**:每条里程碑账写明方向归属。

**标注格式**:

```
方向: T          # 单一方向
方向: C+T        # 复合(主方向在前)
方向: 维护       # 修 bug / 发版 / 文档整理 / 安全修缮 / 护栏
```

- 「维护」不是第四个方向,是**地板**:让三大方向的成果不烂掉的活(修 bug、
  安全修缮、防腐门、发版、文档整理)。地板活不需要论证方向,但要如实标
  「维护」,不许硬蹭方向标签。
- **刻意不设机械门**(commit-msg hook / CI 检查):方向归属是一个判断,不是
  一个形状——机械门只会逼出乱贴的标签,而贴错标签比不贴更坏。这条纪律由
  收口纪律执行(CLAUDE.md §4.1 有对应守则条,账本漏标即算收口不完整)。

## 五、判据速查

给未来的每次开工做三秒自检:

| 你在做的事 | 方向 |
|---|---|
| 工具循环/工具面/沙箱/审批分级/调用韧性/调用效果度量 | T |
| 捕获/蒸馏/检索/分层/遗忘/投影/会话连续性/记忆评测 | M |
| 跨 hub/信任/互操作协议/技能包/信封/治理旅行/协作损耗 | C |
| 修 bug/发版/防腐门/文档整理/安全修缮 | 维护 |
| 以上都说不上 | 先回答「为什么要做」 |

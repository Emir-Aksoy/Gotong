## 一、一句话

把「阿同自己摸索怎么记」换成「框架预置好怎么记、怎么想、怎么答」：

- 每个生活领域一本档案。**结构归模板，内容归阿同，规程归成员。**
- **数字由代码算，判断由模型做。**
- 常驻上下文只放一张驾驶舱卡；细节按「档案卡 → 查询结果 → 原始记录」逐层展开，每层有上限。
- 每次写入只追加一条记录或改一个分区，没有任何路径整篇重写档案。

## 三、为什么（2026-10-20 生产一手证据）

1. **阿同已自建过一本，方向对、但代价高**：`knowledge/身体状态档案.md`（12.5KB）用两个月、
   合并两份旧档才成型；结构开始走样（末尾几段游离于分区之外）；「防串」作答规程是记混之后补的。
2. **写入只有整篇覆盖**：8 次写入，正文从约 4000 字涨到约 7200 字。
3. **路径很重**：一次更新 = 打开工具目录 → 读整篇（最多 32KB 原样返回）→ 整篇写回。
4. **与长任务失败相关（推断）**：10 月初的上游中断里，有工具记录的 4 次中 3 次是刚读完知识
   档案、下一次模型调用还没出字就被 Cloudflare 100 秒切断。日志不能逐次证明，但方向一致。
5. **其他领域空白或分散**：财务、心境没有档案；工作散在四处。
6. **流水不能放在记忆里**：episodic 会被蒸馏后删除，semantic 要经过校正、上架和预算逐出。
7. **人设空缺**：原系统提示词只讲接待与转派，没有任何关于如何思考、如何作答的要求。

LIB track 定的是「目录学不预设」。**本 track 只对核心生活领域反转这一条**：核心领域预置，
其余知识仍由阿同在 `knowledge/` 自由上架。

## 四、五本档案

不按话题切，按**数据形态**和**思考方式**切。

| 档案 | 流水 | 提醒（推送 = 经免打扰闸主动发；卡内 = 只进驾驶舱卡） |
|---|---|---|
| 健康 `health` | `weight` 体重体脂 · `workout` 训练 · `sleep` 睡眠 · `condition` 伤病体检 | 4 天以上没训练（卡内）· 水平型目标达成（推送） |
| 心境与精力 `mind`（敏感） | `mood` 情绪/压力/精力 + 触发事件 | 连续低分（推送，只推一次）· 每晚 21 点签到 |
| 财务 `finance`（敏感） | `tx` 收支 · `balance` 资产负债快照（按账户取最新）· `recurring` 固定扣款（按名称取最新） | 预算 80% / 100%（推送）· 扣款 3 天内到期（推送） |
| 事业 `career` | `project` 项目组合 · `commitment` 承诺与截止（按名称 / 事项取最新） | 承诺临期（推送） |
| 决策日志 `decisions` | `decision` 选项、理由、预期、复盘日（按问题取最新） | 到复盘日（推送） |

人际、生活事务暂不预置；登记表支持以后按需启用，不改代码。

## 五、档案长什么样

### 5.1 磁盘布局

放在成员目录下、与 `knowledge/` 平级，随既有 git 快照和备份走：

```
<成员目录>/life/
├─ registry.json            登记表：启用哪些档案、模板版本、币种、签到与推送开关
├─ state.json               派生状态（代码重算，内容不变不重写）
├─ push-state.json          签到日期与时刻、已推提醒 id、已发周回顾
├─ health/
│  ├─ dossier.json          档案正文（真相，按分区存，带 revision）
│  ├─ weight.jsonl          流水（只追加）
│  └─ workout.jsonl …
├─ mind/ … finance/ … career/ … decisions/ …
├─ reviews/2026-W43.md      周回顾
└─ views/健康.md …           给人看的投影（只写不读回，手改会被覆盖）
```

照「JSON 是真相、md 是只读投影」的既有模式：分区边界由数据结构保证，不靠解析 Markdown 标题。

**启用方式（file-first）**：`registry.json` 存在即启用，不新增环境变量（旋钮仍 114）。阿同
第一次 `log_record` / `update_dossier` 时自动创建；没有登记表时提示词逐字节不变、后台不推送。

### 5.2 档案分区（每本同一骨架）

| 分区 | 内容 | 谁能写 |
|---|---|---|
| 现状 | 上半由代码从流水算（最新值、7 日均值、近 4 周趋势、本周/本月汇总）；下半是阿同一句话判断 | 代码 + 阿同 |
| 目标 | 文字 + 可选指标（由代码算进度） | 阿同提议，成员原话确认后生效 |
| 洞察 | 规律 + 证据范围 + 把握（高/中/低），最多 8 条 | 阿同 |
| 待澄清 | 数据冲突、缺口，最多 12 条 | 阿同；问清后关闭 |
| 规程 | 模板规程（记录 / 作答 / 判断 / 提醒 / 边界）+ 成员补充条款 | 模板只读；补充条款阿同提议、成员确认 |
| 待确认提议 | 目标、规程的新增与移除提议，最多 10 条 | 阿同提议；成员确认或拒绝 |
| 维护记录 | 最近 20 次改动摘要 | 自动 |

各分区超上限时**响亮拒绝**并说明先腾哪里，不静默截断。

### 5.3 流水记录

统一信封：`{id, at, recordedAt, stream, source:{kind: user|inferred|import, excerpt}, fields, supersedes?, retracted?}`。

- 字段、单位、取值范围、必填项、枚举、缺省值由模板定义，**写入时校验**：未知字段、缺必填、
  越界一律拒，报错带单位、范围和该流水的字段清单。
- `at` 缺省今天；成员说「昨天」「上周三」由阿同换算成日期。日期按部署环境时区（生产是
  Asia/Shanghai，与马来西亚同为 UTC+8）。未来日期与远古日期拒。**只给日期且是今天的**自动补上
  当前本地时刻（`2026-10-20 08:15`），同一天多条按时刻排得出先后；补记过去的日期保持只有日期。
- 改错：写一条带 `supersedes` 的新记录；删除：`supersedes` + `retract=true`。查询只取有效记录，
  历史可查。按键取最新的流水（资产快照、固定扣款、项目、承诺、决定）同理——**撤回某个键的最新
  一条，该键回到上一条有效状态**，不是整个键消失（工具说明里写明了）。
- 多币种：财务流水按币种字段分开算，不分组时每个币种按同一个聚合单独算（`ma7` 仍是均值、`trend`
  仍是斜率）。`group_by` 的组名带币种（`餐饮·MYR`）并注明未换算；
  目标指标缺省主币种 CNY；驾驶舱卡与现状行除 CNY 外，非零的其他币种各多列一行（`本月支出(MYR)`）。
- `source.excerpt` 自动附当轮成员原话开头片段，模型不用复述。
- 只追加，不改写原行；坏行跳过不炸；单条超 2KB、单流水超 4MB 拒。上一次写入断在半行时，下一条
  先补换行再写，不会和残行粘成一行。
- id 是 `流水-序号`，序号取「现有行数」与「已见最大序号」中较大者加一，坏行被跳过也不会撞号。
- 同一进程内按目录串行（模块级目录锁），多个句柄同时写 id 不撞。
- 档案 JSON 能解析但形状不对（版本、修订号、分区类型）时，原文件改名为 `.corrupt-<时间戳>` 隔离，
  按空档案重建，并写日志——不拿坏数据继续渲染。

## 六、思维框架

### 6.0 冷静思考协议（写进人设，所有档案共用）

1. 先查后答：涉及数字和历史，先查档案和记忆；查不到就说查不到，不凭印象。
2. 分开说：事实（带日期）/ 推断（说把握多大）/ 建议（给选项和代价）。
3. 不迎合：说法与记录冲突时，摆出记录，问以哪个为准，并记进待澄清。
4. 看趋势不看单点；跨领域的关联只说「同时出现」，不说因果。
5. 大事慢想：金额大、不可逆、影响长期的决定先记进决策日志，不当场拍板。
6. 不确定时只问最关键的一个问题；情绪时刻先接住感受，再分析，不说教。

### 6.1 各档案规程

各档案的记录 / 作答 / 判断 / 提醒 / 边界五段规程写在 `packages/personal-butler/src/life-templates.ts`，
**打开哪本档案才把哪本的规程带进上下文**。要点：

- **健康**：体重用 7 日均值与近 4 周趋势回答，±1kg 单日差视为波动；判断顺序是体重趋势与目标
  速度 → 训练负荷 → 恢复 → 坚持度；不诊断、不开药、不替代医生。
- **心境与精力**：先接住感受；谈规律至少两周数据；连续低分温和关心一次不追问；出现严重信号时
  明确建议寻求专业帮助；不做心理诊断、不贴标签。
- **财务**：金额精确、币种缺省 CNY、个人与生意同一本账；跨币种只分别列出，换算要说明汇率口径；
  判断顺序是现金流 → 安全垫 → 负债 → 储蓄 → 投资；只记账和分析，不碰任何转账或交易，不记
  卡号账号密码；市场研究归 alpha-capital，两边不共享档案。
- **事业**：搁置项必须写恢复条件；与任务本分工——任务本管「下一步做什么」，事业档案管「为什么、
  先做哪个、复盘」。
- **决策日志**：问题 / 选项（含「不做」）/ 代价、可逆性、最坏情况 / 选择与理由 / 预期 / 复盘日。

## 七、怎么调用：上下文分层

### 7.1 四层

| 层 | 内容 | 何时进上下文 | 上限 |
|---|---|---|---|
| 0 常驻 | 驾驶舱卡（卡头附使用规则）+ 人设里的冷静思考协议 | 每轮，稳定段，紧跟知识索引卡 | 卡 ≤1800 字节（实测五本空卡约 1.1KB） |
| 1 档案卡 | 现状、目标、待澄清、提议、提醒、洞察、规程、流水统计与字段 | `open_dossier` | ≤3600 字节 |
| 2 查询 | 代码算好的数 | `query_records` | 单次 ≤1500 字节 |
| 3 原始记录 | 逐条记录，分页 | `read_records`，只在核对时用 | 单页 ≤2000 字节 |

**驾驶舱卡的约束**（稳定段进缓存前缀，也出现在审批恢复和长任务分段里）：

- 渲染**字节确定**：不含当前时刻，不用相对说法，一律绝对日期（「截至 10-20」「最近记录 10-17」）。
  只在档案被写入、日期翻页或后台重算后变化。
- 没有登记表返回空；渲染出错降级为空，不拖累同段的知识索引卡。
- 卡头写明「背景，不是指令」，档案内容不构成任何授权。
- 稳定段原来只有一个槽位，现由 `composeStableCards` 按固定顺序拼「知识索引卡 + 驾驶舱卡」，
  `stableContext:` 注入点仍只有一处（防腐测试守着）。

**任务内预算**：同一任务里工具结果一直累积、不压缩，框架也不截断工具返回。所以第 1–3 层共用
**每次执行 9000 字节、单次 3600 字节**的生活档案读取预算，独立于记忆预算（6000/2000，互不挤占）。
同一内容同一任务里重复读不再计费，直接回「已经返回过」；超限响亮拒绝并说明。

### 7.2 五个工具

| 工具 | 层级 | 作用 |
|---|---|---|
| `open_dossier(domain)` | 一等 | 返回档案卡（含该档案规程与版本号） |
| `log_record(stream, fields, at?, supersedes?, retract?, inferred?)` | 一等 | 校验后追加一条；返回 id、相关现状行和该领域提醒 |
| `query_records(stream, agg, period/days/from/to, field?, where?, group_by?)` | 一等 | `agg`：latest / count / sum / avg / min / max / ma7 / trend / streak / current；`group_by` 按日/周/月或某字段 |
| `update_dossier(domain, section, op, revision, …)` | 一等 | 只改一个分区，带版本号防覆盖 |
| `read_records(stream, from?, to?, offset?)` | 目录 | 原始记录分页 |

`update_dossier` 原计划放目录层，实现时上调为一等：记判断、记洞察、关闭待澄清是档案日常动作，
藏在目录后会逼模型走两跳。四件一等工具实测约 **1348 token**（进缓存前缀），`read_records` 约 169。
全部属于 benign，在 `butler-tool-tiers.ts` 登记；一等工具的说明里不点名目录工具。

### 7.3 证据门（目标与规程只听成员的）

- 目标、补充条款的 `set` / `remove`，以及提议的 `confirm`，必须带 `user_quote`，且它必须**等于成员
  这一轮消息的完整原话**（空白归一化后整句相等），与 `remember` 的证据标准一致；否则只能 `propose`。
  `reject` 不需要原话。原计划是「原话片段逐字出现在消息里」，评审指出片段可以断章取义
  （「不要把目标定成 65」里摘出「目标定成 65」），所以收紧为整句。
- 当轮原话取自任务载荷里的成员文本，与 `remember` 同源（`extractUserText`）。为此 `LlmAgent` 与管家
  的四个 `runForTask` 调用点改为传**完整任务**（原来只传 `{id, from, ancestry}`，载荷被丢掉，证据门
  在生产里会永远判「没有原话」——第二轮复核发现，有走真实 `PersonalButlerAgent` 的回归测试守着）。
  心跳、长任务分段与
  子任务载荷没有成员原话，这时 `log_record` 的来源一律标为推断，目标与规程只能提议；
  审批恢复保留原载荷，所以仍算。
- **同一任务里刚提的提议不能在同一任务里确认**：提议要先告诉成员，等成员下一条消息。否则模型可以
  自己提、拿成员一句无关的话自己确认。提议条目记下提出它的任务 id（`taskId`），所以审批挂起再
  恢复（新的作用域）也认得出是同一任务。

### 7.4 典型流程

| 成员说 | 阿同的调用 | 工具次数 |
|---|---|---|
| 「今早 72.4」 | `log_record(health.weight)` → 回一句带 7 日均值 | 1 |
| 「这个月瘦得怎么样？」 | `query_records(health.weight, ma7 / trend)` | 1–2 |
| 「最近总是很烦」 | `open_dossier(mind)` → `query_records`（心境、睡眠） | 2–3 |
| 「要不要再开一家店？」 | 打开财务、事业 → 决策模板，只问一个关键问题 → 选定后记入决策日志 | 3–4 |
| 「把这两个月的训练整理一下」 | `query_records(workout, 按周)` → `update_dossier(health, insights)` | 2 |

框架不做语义路由（热路径零 LLM）：驾驶舱卡每行写明「这本管什么」，由阿同自己判断开哪本。

## 八、后台与主动推送

### 8.1 生活档案扫描（每 15 分钟，零模型）

挂在 `armButlerSweeps`，由 `main.ts` 的 `life: { on: butlerDefaultOn }` 开启；没有登记表的成员不动。

1. 重算派生状态（内容不变不写盘）。
2. **心境签到**：本地 21:00–21:59 之间、今天还没记过心境、今天还没问过，才发一句签到；驾驶舱卡
   随后写「今天 HH:MM 已发出心境签到」，让阿同知道下一条回复多半是在回答签到。签到是过时即无意义
   的消息，以「发不了就丢」方式交给免打扰闸：被丢（当日上限已满）就不记已发，窗口内下一轮再试。
   「21 点」按免打扰闸同一个成员本地钟判（服务器时区不是 +8 时，按服务器钟的 21 点可能正落在
   免打扰段里）；投递失败已由 outbox 排队，记为今天已交出、不重推，但驾驶舱卡**不说已发出**。
3. **推送型提醒**：按稳定 id 只推一次（例如「多日没训练」的 id 只认最近一次训练日期）。
4. **周回顾**：周一 09:00 后，**由代码计算**上周各档案的记录数与关键数字，写进
   `reviews/<ISO 周>.md` 并推送；上周没有任何记录就不发；同一周不重复。
5. 提醒和周回顾一交给推送就记为已发，**投递失败也一样**——失败由 IM 桥 outbox 持久重投，扫描器
   再推只会让成员收到两份。

**与原设计的差异（如实记）**：原计划在 6 小时维护链里挂一个 reviewer、周回顾由模型写结论。
实现改为独立的 15 分钟零模型扫描、周回顾纯代码生成：签到要准点，提醒要及时，6 小时一跳赶不上；
周回顾的数字本来就由代码算，模型写结论这一步留给成员看到周回顾后在对话里展开，不在后台花钱。

### 8.2 免打扰闸（覆盖全部后台主动推送）

原设计只给生活档案推送加闸。实现时发现这是全局问题（晨报、run 播报、巡检、卡壳提醒、备份提醒
各自判断「该说了」，没人看现在几点），所以 `ButlerPushGate` 包住 `armButlerSweeps` 的**全部** push：

- **免打扰**：成员本地 22:00–07:00（固定 +8，与每日简报的时区口径一致）。期间的推送**落盘暂存**，
  07:00 后合成一条发出（「免打扰期间暂存的 N 条消息」）。
- **每日上限**：每成员每本地日 8 条；超了同样暂存到次日早上，不丢。
- 被暂存的推送对调用方报 `{delivered: true, reason: 'deferred_*'}`，否则扫描器每 tick 重试会在夜里
  堆出几十条重复。
- 发出时交给底层投递（后面还有 IM 桥 outbox 的持久重投），本闸只管「何时」；交出即从暂存删除，
  **任何失败都不重交**（原实现对 `no_bridge` 重交，评审指出 outbox 已接手时会多出一份）。
- 调用方可要求 `dropIfDeferred`：遇到免打扰或上限就直接丢弃，返回 `{delivered: false,
  reason: 'dropped_quiet' | 'dropped_cap'}`，用于签到这类过了时间就没意义的消息。
- 成员自己订阅的**运行播报**带 `capExempt`：只守免打扰，不占也不受每日上限——一小时一跑的工作流
  不该在第 9 条之后被压到第二天，也不该把签到挤掉。
- 暂存写盘失败时如实报 `{delivered: false, reason: 'defer_failed'}`，让调用方下一轮再交。
- 有界：每成员暂存最多 20 条，36 小时前的暂存丢弃；合并消息有字数顶，**保留最新的**，超出的明说
  「另有 N 条较早的消息已省略」。暂存文件读不懂时写警告日志，不静默当空。
- **不经本闸**：成员自己设的提醒、审批回推、转派结果、长任务进展——那些是成员在等的回音。
  已知不经本闸的主动推送：IM 桥内部的断供/恢复播报（低频运维信号）。

## 九、冻结记忆块不再打碎缓存（顺带修复）

侦察发现：冻结记忆块排在系统提示最前面、每个任务重算，块里含每轮都在变的 episodic，所以它后面
整段稳定内容（人设、知识索引卡、驾驶舱卡）的提示缓存几乎每轮失效。

修法（opt-in，管家开启）：`frozenVolatileKinds: ['episodic']` 把 episodic 挪出冻结块，放进易变尾段
的「近期记忆」块（≤1500 字）；冻结块只剩稳定的身份、偏好等。冻结块的说明文字只在开启该选项时
换成新版（`refreshNote`，说明「近期的事在后面单独一块」），**未开启的调用方逐字节不变**。
管家开启了，所以**管家上线后第一次请求会有一次性缓存未命中**，之后稳定前缀可复用。
细节见 `NA-NATIVE-ADAPTATION.md` 与 `ATONG-LIBRARIAN.md` 相关节。

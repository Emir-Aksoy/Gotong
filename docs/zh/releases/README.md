# docs/zh/releases/ — 项目状态快照(每次大版本更新记一篇)

> 这里存的是**周期性、可读的项目整体现状快照**——不是逐 commit 的流水账,也不是
> 某个里程碑当初怎么建的深潜记录。想知道「这个项目现在整体是什么样子」,从
> **最新一篇**读起就够,不用先啃完其它账本。

## 为什么单独开一个目录

仓库里已经有三处记录「发生过什么」,但都不是这个目录要做的事:

- **[`../../../CHANGELOG.md`](../../../CHANGELOG.md)**(根目录)——npm 包的语义化版本
  变更记录,英文,面向「升级到这个版本会有什么改动 / breaking change」,颗粒度是
  单个包的版本号,不是「整个项目现在长什么样」。
- **[`../PROGRESS-LEDGER.md`](../PROGRESS-LEDGER.md)**——按时间线排列的全部里程碑
  散文索引,持续增长、逐条 commit 溯源,面向「这个功能当初是一步步怎么做出来的」。
- **[`../ledger/`](../ledger/README.md)**——逐 Phase / Stream / Route 的开发档案,
  面向「这个具体机制的设计权衡是什么」,密度很高,不是用来「读一遍就懂现状」的。

这个目录不重复它们,而是补一个视角:**每次大版本更新,写一篇能从头读到尾、
说清楚「项目整体现在处于什么状态」的快照**——给隔了几周没看这个项目的人
(包括未来的开发者自己)一个不用先啃几十篇账本就能对齐现状的入口。深挖细节
一律链回上面三处,不在这里重复。

## 怎么写 / 怎么读

- 文件名:`YYYY-MM-DD-<英文 slug>.md`。每次大版本更新写一篇新的,**不改旧文件**
  ——历史快照不回填,想知道「当时」是什么状态就读对应日期那篇。
- 内容不追求全,追求**准且可读**:项目是什么 / 三层北极星现在做到哪 / 生产环境
  现状(不写具体基础设施细节,那是运维层面的东西,不适合放进公开仓库)/ 最近一段
  时间做了什么 / 已知缺口与下一步。
- 想知道「现在项目整体状态」→ 直接读**索引里最新一篇**。

## 审核处理

独立审核发现的问题逐项补了反例：

- 公共 JSON 规范化丢失 `__proto__`、数字样式键顺序不符合 JCS；改为直接按词法输出键值，拒绝非法数值与孤立代理项，Node 接入包共用生成代码。
- 验收曾发生在 JSON 序列化之前；改为先形成实际交付 JSON，再裁剪、检查与签名。
- 非法原请求可能到收口时才失败；入口拒绝。组装失败返回不含原输出和异常细节的最小失败信封，不留下假运行状态。
- 原请求与结果 `replyTo` 曾未共同校验；接收预览和 CLI 均校验。
- 技能测试标准可被审批卡截断；生产入口将完整参数限制为 900 可原样显示字符，超限拒绝。
- 技能评测曾绕过配额/用量链；双臂逐次复用现有预算与记账。
- 发布提示词曾遗漏条件与反例；完整发布内容一起进入投影，预算不足整体省略。
- 数组的 JavaScript `length` 属性曾被当作 JSON 字段；只允许真正的数组索引，对象的 `length` 字段仍合法。
- 接入包底层已核验证据但公开工具输出曾丢失状态；pi、dsh 和 WorkBuddy 现在都展示，Python 明确 `not_checked`。

所有已发现问题已补测试并完成修复。文件系统权限导致的本地端口/进程通信失败，均在授权的测试运行环境重跑；这些环境失败没有被当作业务通过。无签名信封仍合法；本地生成结果时若签名器故障，则返回无输出的最小失败信封，不重新生成密钥冒充原身份。
